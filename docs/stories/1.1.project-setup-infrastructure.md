### Data Models

Based on architecture specification, initial core models to implement in Prisma schema:

**User Model** [Source: docs/architecture.md#data-models]:

```typescript
interface User {
  id: string (UUID)
  email: string (unique)
  phone: string (unique)
  role: UserRole ('customer' | 'provider' | 'admin')
  password_hash: string
  verification_status: VerificationStatus ('unverified' | 'pending' | 'verified')
  created_at: Date
  updated_at: Date
}

interface UserProfile {
  user_id: UUID (foreign key)
  first_name: string
  last_name: string
  avatar_url?: string
  language: string (default 'en')
  address: JSONB
  notification_settings: JSONB
}
```

**Service Provider Extension** [Source: docs/architecture.md#data-models]:

```typescript
interface ServiceProvider {
  user_id: UUID (foreign key to users)
  business_name: string
  description?: string
  services: string[] (array of service categories)
  service_areas: JSONB (geographic coverage)
  pricing: JSONB (pricing structure)
  availability: JSONB (schedule)
  rating: decimal (default 0)
  completed_jobs: integer (default 0)
  response_time_minutes: integer (default 0)
  is_active: boolean (default false)
}
```

## Testing

### Testing Standards

**Test File Locations**:

- Unit tests: `tests/__tests__/` following Jest conventions
- E2E tests: `tests/e2e/` for Playwright tests
- Test utilities: `tests/utils/` for shared test helpers

**Testing Frameworks and Patterns**:

- **Jest**: Unit testing with mocking of external dependencies
- **Playwright**: E2E testing with browser automation
- **Testing patterns**: Repository pattern mocking, API testing with supertest-like functionality
- **Database testing**: Use test database instances, transaction rollback for test isolation

**Specific Testing Requirements for This Story**:

- Database connectivity tests for PostgreSQL and Redis
- Health check endpoint testing with various database states
- Configuration validation tests for environment variables
- Build process testing for TypeScript compilation
- Linting and formatting validation in CI pipeline
